# T15d: optical-input tiny-overfit diagnostic

Registered before these runs. No full training, upload, or held-out selection.

- **D1:** with S1+S2 input (same model and recipe), the worst chip reaches >0.95 and the 8-chip gate reaches >0.9. If both hold, the pipeline is correct and S1-only has an information limit.
- **D2:** if S1+S2 also fails, the cause is in the pipeline, not the inputs.

## Fixed procedure

Use the existing U-Net, seed 17, AdamW lr 0.003, weight decay 0,
BCE + Dice (pos_weight 1), threshold 0.5, batch size 2, no augmentation,
cosine schedule and 400 epochs without early stopping. Native-resolution
train chips only. The eight train rows are [92, 139, 114, 39, 191, 26, 207, 181];
the worst chip is Spain_5678382, row 181. No chip reselection.

Run worst-chip and eight-chip fits for (1) S1 VV/VH plus all 13 S2 bands,
and (2) S2 alone. Use the verified pack band order and train-only normalization
statistics. Non-finite inputs and S2 zero nodata are imputed to the train mean
(normalized zero), preserving the existing mask policy. Primary water IoU pools
TP/FP/FN on label != -1. Save best IoU and the final epoch training loss;
checkpoint selection is train IoU for these diagnostic fits only.

D1 passes only if BOTH S1+S2 conditions hold strictly; ties fail. Otherwise
report D1 FAIL and D2 by its registered rule, then stop for Soham's decision.
The tiny gate remains strictly >0.9. S2-only results are diagnostic, not a
replacement gate. Reuse saved S1-only runs as references; the prior worst-chip
reference used a constant schedule, while the eight-chip reference used cosine.
Do not silently describe those two S1 references as identical recipes.

Overlay target-valid pixels that the saved S1-only worst-chip checkpoint gets
wrong and the new S1+S2 best worst-chip checkpoint gets right on native S2 RGB
(B04, B03, B02). Save outputs/t15-debug/s1_vs_s1s2.png. This is a training-set
memorization diagnostic; it does not establish generalization or product accuracy.
