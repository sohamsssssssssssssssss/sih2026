# T07c — event-window VH Otsu, preregistered 2026-11-17

This replaces the T07b shipped-mask reproduction preflight. It is not necessary
for a newly computed threshold to reproduce the shipped Otsu labels. Part A was
completed independently at d5f7296.

## Fixed method, before held-out evaluation

Compute Otsu on finite VH in dB, over the entire supplied scene/window or all
chips of the same flood event pooled. Use the existing
models.change.sar_water.otsu_threshold: 256 bins and 0.1/99.9 percentile clipping.
Clamp the resulting threshold to [-26, -14] dB. Water is finite VH < threshold;
all non-finite VH is dry. An all-non-finite window produces an all-dry mask and
no numerical threshold. Labels are never used to derive a threshold. No model,
postprocessing, per-chip threshold, morphology or test-driven retry is allowed.

The clamp endpoints are fixed by the user's T07c instruction, before evaluation;
they are not claimed to be a fitted optimum. A TRAIN-only audit will record its
per-event raw/clamped thresholds and clamp impact before any held-out labels
are scored. The audit cannot change endpoints, bins, clipping, or the method.
This is the provenance of their choice; no held-out label tuning is permitted.

For the pack evaluation, pool every available chip of each event across splits,
using imagery and event membership only. This is label-free, transductive scene
context, as when a deployment scene covers the event. Publish the pooling scope
and chip membership; do not call the result an independent-chip evaluation.
Train-only pools are diagnostic and never substituted into final predictions.

## Metrics and fixed verdict

Primary metric: pooled water IoU = TP/(TP+FP+FN), only on hand label != -1.
Non-finite VH remains in the scoring denominator when its hand label is valid.
A zero-union IoU is unknown (null), never silently one. Evaluate train (audit),
valid, test, bolivia, and India-test (the India subset of test, 14 chips).
Report B1 shipped Otsu == 1, B2 original per-chip Otsu, and this tool together.
B2 uses the existing 256-bin helper on finite VH at label-valid pixels, matching
the fixed historical baseline implementation; it is not the new method.

CI95: percentile bootstrap by chip, seed 17, 2000 resamples, aggregate TP/FP/FN
within each resample before dividing. These intervals condition on fixed event
thresholds; they do not measure uncertainty across independent flood events.
India-test is one event. Record all chip counts and undefined-bootstrap counts.

PASS iff the new tool's India-test point IoU >= 0.65. The CI is descriptive and
is not an additional pass criterion. Historical anchors: B1 approximately 0.704,
B2 approximately 0.379. Failure is a reportable verdict, not permission to tune.

Register flood-otsu as experimental_unvalidated for either verdict and attach
an evidence ref to the report. Never mark it validated or invent calibrated
confidence. Document the verdict in core/tool_status.json.
